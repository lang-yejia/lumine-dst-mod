# 旅行手册完整系统：玩法、内容、UI 与实施规格

0.38.0 之后的工作区已完成 D1 事务拆分和离线测试。真实 DST 验收见 `tests/manual/journey.md`。对照 `journey-rebuild-audit.md` 和 `mod/lumine` 当前源码。

## 玩法边界

- 章节有两种解锁方式：体验类达成原版事件后直接结算；记录类需亲历并向自己的派蒙交证物。百科条目可无见闻点，避免通过大量简单物品刷点。
- 记录类按 `chapter_id` 一次结算；证物只暂存一件，完成后放进派蒙六格背包。满格时进入最多两件的持久待返还队列。唯一的奖励权威在服务端。
- 见闻点仍只支付现有旅行技能；百科扩充不修改当前已领取点数和已购买技能。
- 旧档 `done/experienced/insight/skills` 原样保留。后续新增章节使用独立稳定 ID，不插入旧 20 项位图中间。

## 信息架构

```text
旅行手册首页
├─ 继续阅读：最近发现/正在记录/待返还
├─ 饥荒世界
│  ├─ 求生与季节
│  ├─ 地区与地标
│  ├─ 生物与首领
│  └─ 制作、农耕与航海
├─ 莹的旅程
│  ├─ 元素与七天神像
│  ├─ 武器、护甲与合成台
│  ├─ 圣遗物与角色能力
│  └─ 派蒙、兰纳罗小屋
├─ 装备见闻（保留实战/合成台流程）
└─ 旅行技能（保留购买逻辑）
```

- 首页优先展示一张大图、当前进度及三个具体下一步；分类页采用左侧章节导航＋右侧预览；阅读页以大图、简介、正文、相关章节、派蒙评语为主。
- 未发现：剪影、地点线索、奖励。已经历：显示证物图标与物品名。记录中：剩余时间和派蒙状态。已记录：完整正文与评论。
- 分类不等于解锁方式；筛选器可切换“全部/体验/派蒙记录/未完成”。原版与模组以章节来源标识区分。
- 局部替换 Widget，不弹出第二个 Screen，避免此前出现的页面切换闪烁。一次只加载当前页图像；图标必须来自准确的原版或项目资源。

## 章节数据结构

```lua
{
    id="deerclops", source="vanilla", group="boss", region="surface",
    title="寒夜巨影", image={atlas="...", tex="deerclops_eyeball.tex"},
    teaser="冬夜里有巨大的脚步声。", summary="...", body={"段落一", "段落二"},
    related={"winter", "lumine_armor"}, evidence={"deerclops_eyeball"},
    experience="participated_in_kill", reward=3,
    paimon={start="...", complete="...", revisit="..."},
}
```

章节数据与 UI、记录事务分离。构建时校验 ID 唯一、所有关联 ID 存在、证物 prefab 可用、图片资源存在、奖励非负。旧 20 项 ID 与点数保持。

## 事务与失败路径

服务端校验派蒙归属、距离、玩家手持物品、章节与亲历标记。用 DST 的 `GetSaveRecord` 先读快照，再分离一件。叠堆快照只归一化 DST 保存的数量字段。非空容器、外部实体引用和无法序列化的数据拒收，空的天体英雄碎片仍可提交。

计时结束时先调用 `SpawnSaveRecord` 验证能否恢复原物。成功后挂入待返还队列并结算章节，确认入袋再移除记录。用事务编号消解同一存档里重复的队列条目，旧字段 `recording/record_returns` 加载为 `evidence_records`。能识别的恢复失败会保留快照、显示待修复数量，并在下次加载时再试。已结算章节、见闻和技能走原有存档字段。

脚本覆盖提交和返还回调里的模拟存档、队列及旧档恢复。真实 DST 的序列化、petleash 保存、跨分片、回滚和联网仍需验收。进入下一里程碑前按 `tests/README.md` 运行对应测试等级。

## 阶段与验收

- D1：事务、返还、反馈与保存回归；不得再将可食证物错误送入玩家背包。
- D2：章节数据与现有 20 项完整正文、派蒙评论；模组已有系统入册。
- D3：首页、分类目录、阅读页、状态与关联导航，美术接入。
- D4：派蒙书写动作、逐章台词、音效和更多原版百科条目。
- E/F：单人、客户端、双人、断线重进、跨分片、满格、堆叠、损耗、旧档与其他 HUD 模组回归；逐项记录结果。无法启动游戏的检查标记“未执行”，不可当作通过。
